# Arduino LSP setup

This Neovim config is wired to use `clangd` with a compilation database generated by `arduino-cli`.

It does **not** use `arduino-language-server`.

It will attach to:

- `.ino` buffers
- `c` / `cpp` files inside a directory tree that contains `sketch.yaml`, `arduino-cli.yaml`, or an `.ino` sketch file

## What is already handled by this config

- Detects Arduino sketch roots from `sketch.yaml`, `arduino-cli.yaml`, or a nearby `.ino`
- Generates a compile database for Arduino sketch projects with `arduino-cli compile --only-compilation-database`
- Rewrites the generated `compile_commands.json` so `clangd` can use the real sketch files like `src.ino`, not only Arduino's generated `src.ino.cpp`
- Starts `clangd` against that generated compile database
- Uses a project-local `arduino-cli` binary when available
- Uses a project-local `arduino-cli.yaml` when present
- Reads the board FQBN from `sketch.yaml`
- Falls back to `$ARDUINO_FQBN` if `sketch.yaml` does not define `default_fqbn`
- Generates the compile database asynchronously so opening `.ino` files does not block Neovim
- Shows Arduino loading progress in NvChad's bottom statusline area through `LspProgress`
- Attaches additional `c` / `cpp` buffers in the same sketch tree to the existing Arduino `clangd` client

## Why this uses `clangd` directly

This config originally tried `arduino-language-server`.

That failed on this machine because the installed Arduino CLI variants interpret `--source-override` differently from what `arduino-language-server` expects. The result was repeated startup failures from the language server.

Using `arduino-cli` to generate the compile database and then running `clangd` directly is more reliable for this setup and still provides the features you wanted:

- go to definition
- include resolution
- hover
- diagnostics
- completion

## What you still need outside normal NvChad installation

### 1. Install `arduino-cli`

This config will prefer these in order:

- a project-local `.tools/bin/arduino-cli`
- Arduino IDE's bundled CLI
- `arduino-cli` from your `PATH`

If you set this up on another machine, install `arduino-cli` so it is available on your `PATH`.

### 2. Make sure `clangd` is installed

This machine already has it at `/usr/bin/clangd`.

If `clangd` is missing on another machine, install it with your system package manager or through Mason.

### 3. Install your Arduino core and libraries in `arduino-cli`

The language server depends on your board platform being available to `arduino-cli`.

Examples:

```sh
arduino-cli core update-index
arduino-cli core install arduino:avr
arduino-cli lib install "Adafruit NeoPixel"
```

Use the correct core for your board family instead of assuming `arduino:avr`.

## Per-project requirement

Your project-level `arduino-cli.yaml` is supported and will be passed to `arduino-cli`.

That file is useful for:

- extra board manager URLs
- local Arduino data directories
- local library directories and downloads

But it does **not** define the board FQBN the language server needs.

Each sketch project should have a `sketch.yaml` with a board FQBN:

```yaml
default_fqbn: arduino:avr:uno
```

The easiest way to create it is:

```sh
arduino-cli board attach -p /dev/ttyUSB0 -b arduino:avr:uno path/to/sketch.ino
```

That usually writes a `sketch.yaml` beside the sketch.

If you do not want to commit `sketch.yaml`, you can instead export:

```sh
export ARDUINO_FQBN=arduino:avr:uno
```

`sketch.yaml` is the better option because it keeps board selection local to the project.

## Generated files

When an Arduino sketch is opened, this config generates a local build metadata directory:

```text
.arduino-lsp/
```

That directory contains:

- `compile_commands.json`
- Arduino-generated sketch sources
- cached include/build metadata for `clangd`

This directory is editor/build metadata, not hand-edited project source.

## Progress UI

Arduino loading progress is shown in the bottom statusline area, using the same general path NvChad uses for LSP progress messages.

This repo also contains a small local override in [`lua/autocmds.lua`](/Users/garrepi/.config/nvim/lua/autocmds.lua) so NvChad will still show the progress message even when the window is narrower than the default `120` column cutoff.

## Verify it works

Open a sketch directory and check:

```vim
:LspInfo
```

You should see `arduino_clangd` attached for the sketch.

You should also see a short-lived Arduino loading message in the bottom bar while the compile database is being generated.

If it does not start, this config will warn when one of these is missing:

- `arduino-cli`
- `clangd`
- `default_fqbn` in `sketch.yaml` or `$ARDUINO_FQBN`

## Relevant config files in this repo

- [`lua/configs/arduino.lua`](/Users/garrepi/.config/nvim/lua/configs/arduino.lua): Arduino project detection, compile database generation, and `clangd` startup
- [`lua/configs/lspconfig.lua`](/Users/garrepi/.config/nvim/lua/configs/lspconfig.lua): loads the Arduino setup alongside the rest of the LSP config
- [`lua/chadrc.lua`](/Users/garrepi/.config/nvim/lua/chadrc.lua): adds `clangd` to the Mason install list
